# json_parser — спецификация поведения

Версия 1.0.0. Язык: bash 3.2 (macOS) и новее. Зависимостей нет.

## 1. Запуск

```
json_parser.sh [options] [json|file]
```

Источник данных выбирается так:

| Что передали | Откуда берём JSON |
|---|---|
| ничего, stdin — терминал | печатается справка, выход 0 |
| ничего, stdin — труба | читаем stdin целиком |
| `-` | читаем stdin целиком |
| путь к существующему файлу | читаем файл |
| путь к несуществующему `.json` | ошибка `error: no such file: ...`, выход 1 |
| путь к директории | ошибка `error: is a directory: ...`, выход 1 |
| файл без прав чтения | ошибка `error: cannot read file: ...`, выход 1 |
| что-то ещё | считаем самим JSON |

Вход читается целиком в память. BOM в начале отбрасывается.

## 2. Коды выхода

| Код | Когда |
|---|---|
| 0 | JSON разобран успешно |
| 1 | ошибка разбора или ввода |
| 2 | ошибка в аргументах (неизвестная опция, нет значения) |

## 3. Что считается валидным JSON

Разбирается стандарт JSON плюс несколько послаблений под флагами.

Строго по умолчанию:

- объект: `{` пары `ключ:значение` через запятую `}`, последняя запятая запрещена
- массив: `[` значения через запятую `]`, последняя запятая запрещена
- ключ объекта: строка в двойных кавычках
- строки: `"..."`, escape-последовательности `\\ \" \/ \b \f \n \r \t`, `\uXXXX`
- числа: `-?(0|[1-9][0-9]*)(\.[0-9]+)?([eE][+-]?[0-9]+)?` — без ведущих нулей, без `+` в начале, без `.5` и `1.`
- литералы: `true`, `false`, `null`
- пробелы между токенами: пробел, таб, перевод строки, возврат каретки
- управляющие символы внутри строки запрещены (нужен escape)
- повторяющиеся ключи объекта запрещены
- после корневого значения не должно быть ничего, кроме пробелов

Послабления под флагами:

| Флаг | Что разрешает |
|---|---|
| `--allow-duplicate-keys` | повторяющиеся ключи объекта |
| `--allow-trailing-comma` | запятая перед `}` или `]` |
| `--allow-comments` | `//` до конца строки и `/* ... */` |

`\uXXXX`:
- `0000` — ошибка, символ NUL нельзя хранить в bash-переменной
- `D800..DBFF` — старший сурогат, за ним обязателен `\uDC00..\uDFFF`
- `DC00..DFFF` — одиночный младший сурогат, ошибка
- остальное кодируется в UTF-8 (1, 2, 3 или 4 байта)

## 4. Пути

Путь показывает, где лежит значение.

- ключ объекта: `ключ`
- вложенный объект: `родитель.ключ`
- элемент массива: `родитель[индекс]`, индекс с нуля
- ключ, который не похож на `[A-Za-z0-9_-]+`, берётся в кавычки и экранируется как строка JSON: `""`, `"a b"`, `"a\"b"`
- пустой путь (корень) печатается как `(root)`

Примеры:

```
{"a":1}            -> a
{"a":{"b":1}}      -> a.b
{"a":[10,20]}      -> a[0], a[1]
[[1,2],3]          -> [0][0], [0][1], [1]
{"a b":1}          -> "a b"
```

## 5. Режимы вывода

### По умолчанию

Каждое значение — одна строка `путь=значение`.

```
$ json_parser.sh '{"a":1,"b":"x","c":[1,2]}'
a=1
b="x"
c[0]=1
c[1]=2
```

Значение строки печатается в кавычках и с экранированием. Числа, `true`, `false`, `null` — как есть. Пустой объект — `{}`, пустой массив — `[]`.

### `--paths`

Только пути, по одному в строке, без значений.

```
$ json_parser.sh --paths '{"a":{"b":1}}'
a.b
```

### `--types`

Путь, тип и значение.

```
$ json_parser.sh --types '{"a":1,"b":"x"}'
a:number=1
b:string="x"
```

Типы: `string`, `number`, `boolean`, `null`, `object`, `array`.

### `--json`

JSON собирается заново из разобранного дерева. Ключи и значения экранируются по правилам JSON. Порядок ключей сохраняется.

```
$ json_parser.sh --json '{"a":1,"b":[1,2]}'
{"a":1,"b":[1,2]}
```

### `--pretty`

Включает `--json` и печатает с отступом 2 пробела.

```
$ json_parser.sh --pretty '{"a":1,"b":{"c":2}}'
{
  "a": 1,
  "b": {
    "c": 2
  }
}
```

### `--count`

Количество найденных значений (листьев дерева).

```
$ json_parser.sh --count '{"a":1,"b":[1,2],"c":{"d":3}}'
4
```

### `--sort`

Сортирует строки вывода по возрастанию.

### `--filter TEXT`

Оставляет только те значения, в пути которых встречается `TEXT`. Совпадение подстроки, регистр учитывается.

```
$ json_parser.sh --filter b '{"a":1,"b":2,"bb":3}'
b=2
bb=3
```

## 6. Все опции

```
-h, --help              справка
-v, --version           версия
-q, --quiet             ничего не печатать, только код выхода
--validate              проверить и выйти, ничего не печатая
--paths                 только пути
--types                 путь, тип и значение
--json                  json из разобранного дерева
--pretty                json с отступом
--count                 количество значений
--sort                  сортировать строки
--filter TEXT           оставить пути, содержащие TEXT
--max-depth N           предел глубины вложенности, по умолчанию 128
--max-size N            предел размера входа в байтах, по умолчанию 1000000
--allow-duplicate-keys  разрешить повторяющиеся ключи
--allow-trailing-comma  разрешить запятую в конце
--allow-comments        разрешить комментарии
--                      всё после считается источником данных
```

Опции разбираются в любом порядке до первого не-опционного аргумента.

## 7. Ошибки

Все сообщения идут в stderr и начинаются с `error: `.

| Сообщение | Когда |
|---|---|
| `error: empty input` | ввод пустой или состоит только из пробелов |
| `error: unexpected end of input at pos N` | ввод кончился раньше времени |
| `error: unexpected character 'x' at pos N` | неожиданный символ |
| `error: expected ":", got '1' at pos N` | не тот символ, где ждали |
| `error: expected object key at pos N` | ключ не строка |
| `error: expected comma or closing brace at pos N` | плохой разделитель в объекте |
| `error: expected comma or closing bracket at pos N` | плохой разделитель в массиве |
| `error: invalid number '01' at pos N` | число не по формату |
| `error: invalid value at pos N` | значение не началось с буквы или цифры |
| `error: trailing data at pos N: "..."` | после корневого значения что-то есть |
| `error: duplicate key "a" at pos N` | ключ повторился |
| `error: max depth exceeded` | глубже, чем `--max-depth` |
| `error: input too large` | ввод длиннее, чем `--max-size` |
| `error: bad escape 'q' at pos N` | неизвестная escape-последовательность |
| `error: bad unicode escape at pos N` | после `\u` не четыре hex-цифры |
| `error: unpaired surrogate D83D at pos N` | сурогат без пары |
| `error: unsupported unicode escape 0000 at pos N` | `\u0000` |
| `error: unterminated comment at pos N` | `/*` без `*/` |
| `error: control character in string at pos N` | управляющий символ в строке |
| `error: unknown option -x` | неизвестная опция |
| `error: --max-depth needs a number` | опция без значения |

Позиция `pos N` — индекс символа в байтах, с нуля. Для ошибок чтения символа позиция указывает на сам символ, для ошибок конца входа — на конец строки.

## 8. Ограничения

- вход целиком в памяти, потоковой обработки нет
- глубина ограничена `--max-depth`, по умолчанию 128
- `\u0000` не поддерживается
- числа хранятся как текст, точность не теряется
- порядок ключей сохраняется, сортировки по умолчанию нет
- при `--json` пробелы исходника не сохраняются, дерево пересобирается
